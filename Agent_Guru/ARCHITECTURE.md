# Agent Guru - Architecture & Repository Audit

> **Task 1 deliverable** - Repository audit and system mapping  
> Generated by production engineering spec task execution.

---

## 1. System Overview

Agent Guru is a **pure-Python 3.11+** voice-controlled AI assistant.  
The primary package is `Agent_Guru/` (importable as `Agent_Guru`).  
A thin `guru_platform/` directory exists but contains only a README and examples - it is **not a code package**.

There is **no Rust, no C++, no FFI** in this codebase.  
All ML inference runs through Python libraries (faster-whisper, Coqui TTS, InsightFace, PyTorch/ONNX).

## 4. Voice Pipeline Data Flow

The complete voice pipeline from wake word detection to TTS playback:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         VOICE PIPELINE                                  │
│                                                                         │
│  Microphone                                                             │
│      │                                                                  │
│      ▼                                                                  │
│  MicrophoneCapture (speech/audio/capture.py)                           │
│  sounddevice @ 16kHz mono float32                                       │
│      │                                                                  │
│      ▼                                                                  │
│  AudioProcessor (speech/audio/processor.py)                            │
│  VAD → Noise Reduction (noisereduce) → AGC → Echo Cancel               │
│      │                                                                  │
│      ▼                                                                  │
│  WakeWordDetector (speech/audio/wake_word.py)                          │
│  Vosk offline speech recognition OR energy-based fallback              │
│  Detects: "Hey Guru" → PersonalityType.GURU                            │
│           "Hey Maya" → PersonalityType.MAYA                            │
│      │ WakeWordDetection(wake_word, personality, confidence, timestamp) │
│      ▼                                                                  │
│  BackgroundServiceManager (speech/background_service.py)               │
│  State: SLEEP → WAKE transition, triggers recording                    │
│      │                                                                  │
│      ▼                                                                  │
│  MicrophoneCapture.capture(duration=N)                                 │
│  Records user command audio                                             │
│      │ np.ndarray (float32, 16kHz)                                     │
│      ▼                                                                  │
│  WhisperTranscriber (speech/stt/whisper_stt.py)                        │
│  faster-whisper base model, VAD filter, word timestamps                │
│      │ TranscriptionResult(text, language, confidence, segments)       │
│      ▼                                                                  │
│  CommandParser (speech/commands/command_parser.py)                     │
│  Regex pattern matching → 50+ command patterns                         │
│  OR                                                                     │
│  ReasoningEngine (reasoning/engine.py)                                 │
│  Fast path (trie router) OR Full pipeline (neural + LLM fallback)      │
│      │ Intent(type, parameters, confidence)                            │
│      ▼                                                                  │
│  ┌──────────────────────────────────────────────────────────┐          │
│  │              ACTION ROUTING                              │          │
│  │                                                          │          │
│  │  OS Action?  → OSController (platform/os_controller.py) │          │
│  │              → PlatformIntegration (speech/platform_integration.py)│
│  │              → WindowsIntegration / MacOSIntegration     │          │
│  │                                                          │          │
│  │  LLM Query?  → LLMRuntime (llm/runtime.py)              │          │
│  │              → ProviderAdapter (ollama/openai/gemini/    │          │
│  │                                 anthropic)               │          │
│  │              → KnowledgeGraph (memory/knowledge_graph.py)│          │
│  └──────────────────────────────────────────────────────────┘          │
│      │ response text                                                    │
│      ▼                                                                  │
│  CoquiTTSEngine (speech/tts/tts_engine.py)                             │
│  Coqui TTS, personality-specific voice (Guru=male, Maya=female)        │
│  GPU-accelerated synthesis                                              │
│      │ WAV bytes                                                        │
│      ▼                                                                  │
│  Audio Playback (sounddevice / platform audio)                         │
│      │                                                                  │
│      ▼                                                                  │
│  BackgroundServiceManager → SLEEP (after timeout)                      │
└─────────────────────────────────────────────────────────────────────────┘
```

### Pipeline Stage Latency Targets

| Stage | Target | Implementation |
|---|---|---|
| Wake word detection | <200ms | Vosk (heavier than pvporcupine) |
| Audio capture | ~1-5s | User command duration |
| STT transcription | <1s (GPU) | faster-whisper base model |
| Intent classification | <50ms | Trie fast path; neural fallback |
| LLM response (first token) | <2s | Ollama local / cloud API |
| TTS synthesis | <200ms (GPU) | Coqui TTS |
| **End-to-end** | **<2.5s** | Excluding user speech duration |

## 9. Gaps, Issues, and Missing Integrations

### Critical Gaps

1. **No end-to-end pipeline wiring** - `SpeechEngine`, `ReasoningEngine`, `OSController`, and `LLMRuntime` are all implemented independently but there is no top-level orchestrator that wires them together into a running voice loop. Task 15.1 must create this.

2. **Wake word uses Vosk, not pvporcupine** - Vosk is a full speech recognition engine (~50MB model). pvporcupine is purpose-built for wake word detection (<1MB, <5% CPU). The current implementation will exceed the <10% CPU idle target.

3. **No `ConversationMemory` with LRU** - The design specifies a 50-turn LRU conversation store. The `KnowledgeGraph` is a general entity graph. A dedicated `ConversationMemory` class is missing.

4. **No ring buffer for audio** - The design specifies a 10-second lock-free ring buffer for continuous wake word monitoring. `MicrophoneCapture` does blocking `sd.rec()` calls, not continuous streaming.

5. **TTS playback not integrated** - `CoquiTTSEngine.synthesize()` returns WAV bytes. There is no code that plays these bytes back through the speaker in the main pipeline.

6. **Intent parser not connected to reasoning engine** - `CommandParser` (speech module) and `ReasoningEngine` (reasoning module) both do intent classification. They are not connected; the pipeline must choose one or chain them.
