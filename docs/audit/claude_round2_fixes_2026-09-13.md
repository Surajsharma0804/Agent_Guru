## What this round deliberately did NOT do, and why

- **Did not migrate `MemoryManager` onto the existing ChromaDB/RAG stack in `reasoning/memory/`.** That stack is well-built but completely unwired and untouched by any existing code path; migrating to it is the highest-risk change available at a time when the real pipeline can't be executed end-to-end. Letta's own published LoCoMo benchmark (74.0% filesystem/search vs. 68.5% graph-based) also tempers the assumption that the more complex stack is automatically better. See `world_state_report.md` §5-7.
- **Did not wire the orphaned `reasoning/tools/external/messaging.py` framework in as-is.** Its `SendWhatsAppTool`/`SendSMSTool`/etc. are hardcoded fake-success placeholders; wiring them in unmodified would make the agent confidently report messages as sent that never left the process.
- **Did not build automated "press send" WhatsApp browser automation.** Real, if not precisely quantifiable, account-ban risk (WhatsApp bans 8M+ accounts/month for automated/abusive behavior, per their own Help Center) outweighs the convenience for what is meant to be the user's own persistent account, not a disposable bot number.
- **Did not wire `presentation.py` into the live pipeline.** Built and independently verified as a standalone capability first, with the exact wiring plan documented in its module docstring, rather than risking an unverified edit deep into the orchestrator's ~2800-line dispatch tables without the ability to run the real pipeline.
